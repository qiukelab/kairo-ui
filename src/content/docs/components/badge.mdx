## Installation

```bash
npx kairo-ui@latest add badge
```

## Usage

```tsx
import { Badge } from '@/components/ui/badge'
```

```tsx
<Badge variant="soft">Pro</Badge>
```

## Variants

No variant draws a border. Emphasis comes entirely from the fill, which is why the variants are
named after what they look like rather than after an outline.

| Variant       | Fill              | Reach for it when                             |
| ------------- | ----------------- | --------------------------------------------- |
| `default`     | Solid primary     | The badge is the loudest thing in its row.    |
| `secondary`   | Solid neutral     | A label that should sit level with body text. |
| `soft`        | 10% primary tint  | Coloured, but quiet. The workhorse.           |
| `muted`       | Muted surface     | Metadata — a category, a job type, a count.   |
| `destructive` | Solid destructive | Failures and expiries only.                   |

<Callout>
  There is no `outline` variant. If you need one badge to stand apart from the surface behind it,
  reach for a stronger fill rather than a line — a border on a pill this small reads as noise at
  body-text sizes.
</Callout>

## Sizes

<ComponentPreview name="badge-sizes-demo" />

Padding, text size and icon size move together, so a badge stays proportionate at every step:

| Size      | Text | Use                                 |
| --------- | ---- | ----------------------------------- |
| `sm`      | 11px | Dense labels inside table rows.     |
| `default` | 12px | Everything else.                    |
| `lg`      | 14px | Filter chips, usually with an icon. |

```tsx
<Badge size="sm" variant="muted">
  Freelance
</Badge>
```

## Icons

An icon is a child, not a prop — which means you choose the side:

```tsx
<Badge variant="soft">
  <CheckIcon />
  Verified
</Badge>

<Badge size="lg">
  All listings
  <CheckIcon />
</Badge>
```

Direct `svg` children are sized by the badge's `size` variant and made non-interactive, so an
icon never needs its own classes. An explicit `className` on the icon still wins.

## Links

A badge renders a `span`. To make it navigate, hand it an anchor:

```tsx
<Badge variant="muted" asChild>
  <a href="/changelog">v0.1.0</a>
</Badge>
```

Hover styles are written as `[a&]:hover:bg-muted/70` — they apply only when the rendered element
is actually an anchor. A static badge gets no hover affordance, because nothing happens when you
click it.

## Status dots

There is no `dot` variant; compose one instead:

```tsx
<Badge variant="muted">
  <span className="size-1.5 rounded-full bg-primary" />
  Operational
</Badge>
```

<Callout>
  Colour alone is not a status indicator. Keep the text label — a red dot and a green dot are the
  same dot to a reader with deuteranopia.
</Callout>

## API

| Prop      | Type                                                   | Default   |
| --------- | ------------------------------------------------------ | --------- |
| `variant` | `default \| secondary \| soft \| muted \| destructive` | `default` |
| `size`    | `sm \| default \| lg`                                  | `default` |
| `asChild` | `boolean`                                              | `false`   |

Both are mirrored to the DOM as `data-variant` and `data-size`, so a parent can target them
without knowing the class list.
