## Installation

```bash
npx kairo-ui@latest add input
```

## Usage

```tsx
import { Input } from '@/components/ui/input'
```

```tsx
<Input type="email" placeholder="you@example.com" />
```

`Input` is a bare `<input>`. On its own it has no label, and a placeholder is not one — it
disappears the moment someone types, taking the field's meaning with it. Everything below wraps
it in [`Field`](/docs/components/field), which supplies the label and the wiring.

## Field

Use `Field`, `FieldLabel` and `FieldDescription` to create an input with a label and a
description.

<ComponentPreview name="input-field-demo" align="start" />

```tsx
<Field>
  <FieldLabel>Username</FieldLabel>
  <FieldControl>
    <Input placeholder="Enter your username" />
  </FieldControl>
  <FieldDescription>Choose a unique username for your account.</FieldDescription>
</Field>
```

No `id` appears anywhere. `Field` generates one, `FieldLabel` points `htmlFor` at it and
`FieldControl` puts it on the input — so the label cannot come unstuck from its field.

## Disabled

Pass `disabled` to `Field` rather than to the input. It reaches the control **and** dims the
label and description, which a `disabled` on the input alone cannot do.

<ComponentPreview name="input-disabled-demo" align="start" />

```tsx
<Field disabled>…</Field>
```

## Invalid

Pass `invalid` to `Field`. It sets `aria-invalid` on the control — the same attribute that tells
assistive technology about the error is what draws the red border — turns the label
destructive, and adds the error to `aria-describedby`.

<ComponentPreview name="input-invalid-demo" align="start" />

```tsx
<Field invalid>
  <FieldLabel>Invalid Input</FieldLabel>
  <FieldControl>
    <Input defaultValue="Error" />
  </FieldControl>
  <FieldError>This field contains validation errors.</FieldError>
</Field>
```

<Callout>
  Never style an error with a class alone. A red border communicates nothing to a screen reader;
  `aria-invalid` is what makes the state perceivable, and here it is also what makes it visible.
</Callout>

## Required

Pass `required` to `Field`. The control gets the native `required` attribute and the label grows
an asterisk — marked `aria-hidden`, because `required` is already announced and "star" would only
duplicate it.

## Inline

Use `Field` with `orientation="horizontal"` to lay the control out in a row. Pair it with a
`Button` for a search field.

<ComponentPreview name="input-inline-demo" />

```tsx
<Field orientation="horizontal">
  <FieldLabel className="sr-only">Search</FieldLabel>
  <FieldControl>
    <Input type="search" placeholder="Search..." className="flex-1" />
  </FieldControl>
  <Button type="submit">Search</Button>
</Field>
```

A description or error inside a horizontal field breaks onto its own line, so the row stays
readable when validation fails.

## Grid

`FieldGroup` is a grid. Give it column classes to place fields side by side.

<ComponentPreview name="input-grid-demo" align="start" />

```tsx
<FieldGroup className="gap-4 sm:grid-cols-2">
  <Field>…</Field>
  <Field>…</Field>
</FieldGroup>
```

The columns only apply from `sm` up, so the fields stack on a phone rather than being squeezed
into halves.

## Badge

`FieldLabel` is a flex row, so a [`Badge`](/docs/components/badge) can sit in it to flag a
field.

<ComponentPreview name="input-badge-demo" align="start" />

```tsx
<FieldLabel>
  Webhook URL
  <Badge variant="muted" size="sm" className="ml-auto">

  </Badge>
</FieldLabel>
```

## Input Group

To put an icon, a prefix or a button **inside** the input's border, use
[`InputGroup`](/docs/components/input-group).

<ComponentPreview name="input-group-demo" align="start" />

```tsx
<InputGroup>
  <InputGroupAddon>
    <InputGroupText>https://</InputGroupText>
  </InputGroupAddon>
  <FieldControl>
    <Input placeholder="example.com" />
  </FieldControl>
  <InputGroupAddon align="end">
    <InfoIcon aria-hidden />
  </InputGroupAddon>
</InputGroup>
```

## Sizing

The field is `h-9` and full-width. Constrain it from the parent rather than on the input:

```tsx
<div className="max-w-sm">
  <Input />
</div>
```

Font size is `text-base` below `md` and `text-sm` above it. That is deliberate — iOS Safari zooms
the viewport when a focused field is under 16px, and the jump is disorienting.

## API

`Input` takes every native `input` attribute and adds nothing. Its states come from the DOM:

| State       | Driven by                |
| ----------- | ------------------------ |
| Focus       | `:focus-visible`         |
| Disabled    | the `disabled` attribute |
| Invalid     | `aria-invalid`           |
| File button | the `file:` variant      |

Because there is no prop to learn, anything that works on a native input works here — `pattern`,
`inputMode`, `autoComplete`, uncontrolled `defaultValue`, a `ref`.
