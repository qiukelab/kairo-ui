## Installation

```bash
npx kairo-ui@latest add card
```

## Usage

```tsx
import {
  Card,
  CardAction,
  CardContent,
  CardDescription,
  CardFooter,
  CardHeader,
  CardTitle,
} from '@/components/ui/card'
```

```tsx
<Card>
  <CardHeader>
    <CardTitle>Invite a teammate</CardTitle>
    <CardDescription>They get access immediately.</CardDescription>
  </CardHeader>
  <CardContent>{/* … */}</CardContent>
  <CardFooter>
    <Button>Send invite</Button>
  </CardFooter>
</Card>
```

## Anatomy

| Slot              | Role                                                                                               |
| ----------------- | -------------------------------------------------------------------------------------------------- |
| `Card`            | The container. Owns the elevation, radius, background and vertical rhythm.                         |
| `CardHeader`      | Title area. A CSS grid, so an action can sit beside the text.                                      |
| `CardTitle`       | Heading text. Renders a `div` — pick your own heading level with `asChild` if the outline matters. |
| `CardDescription` | Supporting copy in `--muted-foreground`.                                                           |
| `CardAction`      | Top-right slot for a button, menu or badge.                                                        |
| `CardContent`     | The body. Horizontal padding only.                                                                 |
| `CardFooter`      | Actions. Flex row.                                                                                 |

## Props

| Prop   | Type            | Default   |
| ------ | --------------- | --------- |
| `size` | `default \| sm` | `default` |

`size` is mirrored to the DOM as `data-size`, so a parent can style against it without prop
drilling.

## Elevation, not a border

A card has no border. It lifts off the page with `shadow-card`, a token deliberately kept light
enough to read as separation rather than as decoration.

That token changes **shape** between themes:

```css
:root {
  --shadow-card:
    0 1px 2px -1px oklch(0.16 0.008 254 / 0.1), 0 2px 6px -1px oklch(0.16 0.008 254 / 0.06);
}

.dark {
  --shadow-card: 0 0 0 1px oklch(1 0 0 / 0.07), 0 2px 8px -2px oklch(0 0 0 / 0.6);
}
```

A blurred shadow is close to invisible on a dark surface, so in dark mode the first layer has
zero blur and 1px spread — it draws the hairline the light theme gets for free from its shadow.
Because `box-shadow` takes both forms, one `shadow-card` utility is correct in both themes and
the component needs no dark-mode branch.

Raise a card on hover with the matching step:

```tsx
<Card className="transition-shadow hover:shadow-card-hover">…</Card>
```

## Spacing

Every inset on a card — the vertical padding, the gap between sections, the horizontal padding
on each slot — comes from one custom property that `Card` declares on itself:

```css
--card-spacing: --spacing(6); /* size="default" */
--card-spacing: --spacing(4); /* size="sm" */
```

Slots read it as `px-(--card-spacing)` rather than `px-6`. That indirection is what makes the
inset a value your _content_ can reach as well, which is the whole basis of
[edge-to-edge content](#edge-to-edge-content) below — a number hard-coded as `-mx-6` would
silently be wrong on a small card.

Override it for one card without touching the component:

```tsx
<Card className="[--card-spacing:--spacing(8)]">…</Card>
```

## Dividers

`CardHeader` and `CardFooter` react to a `border-b` or `border-t` on themselves and add the
padding a divider needs:

```tsx
<CardHeader className="border-b">…</CardHeader>
<CardFooter className="border-t">…</CardFooter>
```

The rule behind it is `[.border-b]:pb-(--card-spacing)` — a self-referencing selector, so the
spacing appears only when the border does. There is no `divided` prop to remember.

Those dividers draw in `--border-soft`, one step lighter than the `--border` used for page-level
structure. A card is already separated from the page by its elevation, so a line inside it only
has to group things, not to do the separating — at full strength it reads as clutter.

| Token           | Job                                                     |
| --------------- | ------------------------------------------------------- |
| `--border`      | Page structure: the tabs rail, the sidebar, code blocks |
| `--input`       | A control's own outline                                 |
| `--border-soft` | A divider inside an already-elevated surface            |

The slots carry `border-border-soft` unconditionally. Border-width is `0` by default, so the
colour lies dormant until you add `border-b`. If you want the full-strength line back, say so and
`tailwind-merge` lets you win:

```tsx
<CardHeader className="border-b border-border">…</CardHeader>
```

## Edge-to-edge content

<ComponentPreview name="card-edge-to-edge-demo" />

Cancel the inset with a negative margin of the same size, and the content runs to both edges
while still lining up with everything above it:

```tsx
<CardContent className="-mx-(--card-spacing) -mb-(--card-spacing)">
  <div className="border-y border-border-soft px-(--card-spacing) py-4">…</div>
</CardContent>
```

`-mb-(--card-spacing)` is the second half of the trick: without it the card's own
`gap-(--card-spacing)` leaves a band between the section and the footer, and the hairline stops
reading as the boundary between them. The footer then asks for its top padding directly with
`pt-(--card-spacing)`, since it has no `border-t` to trigger the automatic rule.

## Image

<ComponentPreview name="card-image-demo" />

An image goes before `CardHeader`, on a card that has given up its top inset:

```tsx
<Card className="overflow-hidden pt-0">
  <img src="/your-image.jpg" alt="" className="aspect-video w-full object-cover" />
  <CardHeader>…</CardHeader>
</Card>
```

`pt-0` lets the image start at the very top and `overflow-hidden` clips it to the card's radius.
Give the image a fixed aspect ratio so the card does not reflow as it loads.

<Callout>
  The demo points at `/placeholder.svg`, an asset of this docs site. Copying the code gives you a
  broken image until you swap the `src` for your own.
</Callout>

## CardAction

`CardHeader` switches to a two-column grid only when a `CardAction` is present:

```tsx
'has-data-[slot=card-action]:grid-cols-[1fr_auto]'
```

The header queries its own subtree for the slot, so nothing needs to be threaded down from the
parent.

```tsx
<CardHeader>
  <CardTitle>Usage</CardTitle>
  <CardDescription>Current billing period</CardDescription>
  <CardAction>
    <Badge variant="secondary">Pro</Badge>
  </CardAction>
</CardHeader>
```

## Headings

`CardTitle` is a `div` because a card can appear anywhere in a document and there is no heading
level that is right everywhere. Where the outline matters, promote it:

```tsx
<CardTitle asChild>
  <h3>Invite a teammate</h3>
</CardTitle>
```

<Callout>
  `asChild` on `CardTitle` requires the `Slot` import already used by Button. If you copied
  `card.tsx` alone, add it before using this pattern.
</Callout>
