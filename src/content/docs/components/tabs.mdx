## Installation

```bash
npx kairo-ui@latest add tabs
```

## Usage

```tsx
import { Tabs, TabsContent, TabsList, TabsTrigger } from '@/components/ui/tabs'
```

```tsx
<Tabs defaultValue="account">
  <TabsList>
    <TabsTrigger value="account">Account</TabsTrigger>
    <TabsTrigger value="password">Password</TabsTrigger>
  </TabsList>
  <TabsContent value="account">…</TabsContent>
  <TabsContent value="password">…</TabsContent>
</Tabs>
```

Each `TabsTrigger` is paired with the `TabsContent` carrying the same `value`.

## The rail

Tabs are a rule with an indicator sliding along it — no filled container, no pill. Triggers size
to their own content and align left, so a two-tab set does not stretch across the viewport.

The indicator is an `::after` pseudo-element on the active trigger, offset by `-bottom-px` so its
2px bar lies over the list's 1px rule and the two read as one line. Nothing is inserted or
removed when the selection changes, so switching tabs cannot shift layout.

To centre or distribute the triggers, style the list — the component does not guess:

```tsx
<TabsList className="justify-center">…</TabsList>
<TabsList className="[&>*]:flex-1">…</TabsList>
```

## Keyboard behaviour

Radix implements the WAI-ARIA tabs pattern. Arrow keys move between tabs, `Home` and `End` jump
to the ends, and the tab list is a single stop in the page's tab order — so `Tab` moves past the
whole control rather than through every trigger.

## Controlled

```tsx
const [tab, setTab] = useState('account')

<Tabs value={tab} onValueChange={setTab}>
  {/* … */}
</Tabs>
```

Useful when the active panel belongs in the URL:

```tsx
const [params, setParams] = useSearchParams()

<Tabs
  value={params.get('tab') ?? 'account'}
  onValueChange={(value) => setParams({ tab: value })}
>
```

## Orientation

```tsx
<Tabs orientation="vertical">
  <TabsList>
    <TabsTrigger value="account">Account</TabsTrigger>
    <TabsTrigger value="password">Password</TabsTrigger>
  </TabsList>
  <TabsContent value="account">…</TabsContent>
</Tabs>
```

One prop is enough. `orientation` swaps which arrow keys navigate, and Radix stamps
`data-orientation` on every part — the component reads it to turn the row into a column and move
the rule and its indicator to the left edge. There is no second class to remember, and therefore
no way to end up with a control that looks vertical but navigates horizontally.

## Not navigation

Tabs swap content inside one page. If each panel is really a separate page — with its own URL,
its own back-button behaviour, its own title — use links and a router, not this component.

<Callout>
  `TabsContent` unmounts hidden panels by default. Anything expensive to mount, or holding unsaved
  form state, needs `forceMount` plus your own `hidden` handling.
</Callout>

## API

| Prop                      | Type                                 | Default      |
| ------------------------- | ------------------------------------ | ------------ |
| `defaultValue`            | `string`                             | —            |
| `value` / `onValueChange` | `string` / `(value: string) => void` | —            |
| `orientation`             | `horizontal \| vertical`             | `horizontal` |
| `activationMode`          | `automatic \| manual`                | `automatic`  |

`activationMode="manual"` requires Enter or Space to switch panels. Worth it when a panel
triggers a network request — with automatic activation, arrowing past three tabs fires three
requests.
