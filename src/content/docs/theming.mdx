Every colour, radius and font in kairo-ui resolves through a CSS variable. No component
contains a literal hex code, which is what makes retinting the whole library a single-file
change.

## The two layers

Tokens are defined in two passes, and the distinction matters.

**Raw values** live on `:root` and are overridden on `.dark`. These are the actual colours.

**Utility mappings** live in `@theme inline` and turn each raw value into a Tailwind utility.
`inline` is the important word: it makes the utility resolve `var(--primary)` at the point of
use, so `bg-primary` follows the `.dark` override instead of freezing the light value at build
time.

```css title="src/styles/globals.css"
@import 'tailwindcss';

@custom-variant dark (&:is(.dark *));

:root {
  --radius: 0.5rem;
  --background: oklch(1 0 0);
  --foreground: oklch(0.16 0.008 254);
  --primary: oklch(0.546 0.245 262.881);
  --primary-foreground: oklch(0.985 0 0);
  --border: oklch(0.885 0.008 254);
  --surface-soft: oklch(0.965 0.015 254);
}

.dark {
  --background: oklch(0.15 0.012 254);
  --foreground: oklch(0.96 0.006 254);
  --primary: oklch(0.707 0.165 254.624);
  --primary-foreground: oklch(0.15 0.012 254);
  --border: oklch(1 0 0 / 13%);
  --surface-soft: oklch(0.22 0.02 254);
}

@theme inline {
  --color-background: var(--background);
  --color-foreground: var(--foreground);
  --color-primary: var(--primary);
  --color-primary-foreground: var(--primary-foreground);
  --color-border: var(--border);
  --color-surface-soft: var(--surface-soft);

  --radius-sm: calc(var(--radius) * 0.6);
  --radius-md: calc(var(--radius) * 0.8);
  --radius-lg: var(--radius);
  --radius-xl: calc(var(--radius) * 1.4);
}
```

## The token set

| Token                                    | Used for                                                                      |
| ---------------------------------------- | ----------------------------------------------------------------------------- |
| `--background` / `--foreground`          | Page surface and body text.                                                   |
| `--card` / `--card-foreground`           | Raised panels. Identical to background in light mode; a lighter step in dark. |
| `--popover` / `--popover-foreground`     | Floating layers — dialogs, menus, palettes.                                   |
| `--primary` / `--primary-foreground`     | The brand action colour and what sits on it.                                  |
| `--secondary` / `--secondary-foreground` | Low-emphasis fills.                                                           |
| `--muted` / `--muted-foreground`         | Backgrounds and text that should recede.                                      |
| `--accent` / `--accent-foreground`       | Hover and active states.                                                      |
| `--destructive`                          | Irreversible actions.                                                         |
| `--border` / `--input`                   | Hairlines and field outlines.                                                 |
| `--ring`                                 | Focus ring.                                                                   |
| `--surface-soft`                         | Tinted insets — code blocks, callouts, table headers.                         |

Each pair is contrast-checked in both themes. `--primary` is lighter in dark mode for exactly
this reason: the light-mode blue only reaches 2.4:1 against the dark background, which fails
AA. The lighter step clears it at roughly 6.2:1 and inverts `--primary-foreground` to match.

## Why oklch

Values are written in `oklch(L C H)` rather than hex. Lightness is perceptual, so holding `L`
constant while changing hue produces colours that genuinely look equally bright — a claim HSL
cannot make. It also means a ramp can be generated by walking `L` and `C` without the muddy
midpoints that plague sRGB interpolation.

## Retinting

Change the hue and every component follows. The neutrals in kairo-ui are not grey — they carry
a small amount of chroma at hue `254`, which is what stops the interface reading as generic.

```css
:root {
  /* Blue → violet: rotate the hue on primary and the neutrals together. */
  --primary: oklch(0.546 0.245 292);
  --foreground: oklch(0.16 0.008 292);
  --border: oklch(0.885 0.008 292);
  --surface-soft: oklch(0.965 0.015 292);
}
```

<Callout>
  Rotate the neutrals as well as the accent. Leaving neutrals at the old hue is the single most
  common reason a retinted theme looks subtly wrong — the greys fight the accent instead of
  supporting it.
</Callout>

## Radius

One value drives four steps:

```css
:root {
  --radius: 0.5rem;
}
```

`--radius-sm` through `--radius-xl` are derived with `calc()`, so the whole interface gets
sharper or softer together. kairo-ui ships `0.5rem` — flatter than the shadcn default of
`0.625rem`.

## The brand ramp

Alongside the semantic tokens there is a static `brand-50` … `brand-950` scale:

```css
@theme {
  --color-brand-500: oklch(0.623 0.214 259.815);
  --color-brand-600: oklch(0.546 0.245 262.881);
}
```

This block is **not** `inline`, deliberately. These are fixed hues that must not flip with the
theme — they are for gradients and decorative washes that should look the same in both modes.
Use semantic tokens for anything a user reads or clicks.

## Typography

```css
:root {
  --font-sans: 'Noto Sans Thai', 'Inter', ui-sans-serif, system-ui, sans-serif;
  --font-mono: 'JetBrains Mono', ui-monospace, Menlo, Consolas, monospace;
}
```

Thai comes first in the stack so Thai glyphs render from a font designed for them rather than
falling back mid-sentence, while Latin text still picks up Inter.
