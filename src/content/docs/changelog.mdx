## Unreleased

### Added — tables, overlays and form controls

Eight components: **Table**, **Checkbox**, **Select**, **Popover**, **Hover Card**, **Empty**,
**Command** and **Drawer** — plus two pages that are recipes rather than components, because
neither has a file to install:

- **Combobox** is a `Popover` holding a `Command`. `Popover` exists mainly so this can.
- **Data Table** is `Table` plus [`@tanstack/react-table`](https://tanstack.com/table), covering
  sorting, filtering, row selection, column visibility and pagination. Server-driven tables are
  named as out of scope rather than half-shown.

Details worth knowing:

- **Checkbox has three states.** `checked="indeterminate"` reports `aria-checked="mixed"` and
  draws its own glyph — the state a select-all needs when only some rows are chosen. Claiming
  `true` there would say every row is selected.
- **Table brings its own scroll container** and sets `scope="col"` on every `TableHead`. A table
  cannot be made to fit, so the overflow is not left to the caller to remember.
- **Empty goes inside a table**, in one cell spanning every column. As a sibling it leaves a
  `tbody` with no rows — invalid, and announced as a table of nothing.
- **Drawer is not a second Sheet.** The difference is the drag gesture, not the direction; the
  handle is `aria-hidden` because dragging has no keyboard equivalent, which makes `DrawerClose`
  and Escape load-bearing.

### Changed

- **The site's own ⌘K search now uses `Command`.** It previously hand-rolled every cmdk class, so
  shipping the component without this would have left two copies of the same styling and a docs
  site demonstrating something it did not use. Its behaviour is unchanged, including the
  `value={group + title}` fix that stops hidden description text winning a match.
- **The Components sidebar is alphabetical.** At 27 entries the previous order — roughly
  by relation, never quite consistently — had stopped being scannable.

### Added — seven components

- **Accordion**, **Alert**, **Alert Dialog**, **Aspect Ratio**, **Attachment**, **Avatar** and
  **Dropdown Menu**.
- **Avatar** ships more than the primitive: `AvatarBadge` for a status dot outside the circle,
  `AvatarGroup` for an overlapping row, and `AvatarGroupCount` for the trailing "+3" — which
  takes `asChild`, because an icon there means the slot is an action and should be a button.
- **Alert Dialog** has no close button by design. Radix already blocks outside-click and Escape;
  adding an X would restore the escape hatch and leave you with a `Dialog` under another name.
  `AlertDialogAction` and `AlertDialogCancel` wrap a real `Button` through `asChild`, so they
  take every Button prop and copy none of its classes.
- **Attachment** has no upstream primitive, so its shape is a decision: `AttachmentGroup` owns
  `layout` (`grid | list`) and `Attachment` owns `status` (`idle | uploading | error`), both
  distributed by context. `AttachmentDropzone` wraps a real, focusable file input and reports
  through `onFiles` — it holds no file list, because the caller's form already has one.
- `formatFileSize` in `@/lib/format`, installable as the `format` registry item.

### Fixed — animation utilities were never declared

- **`tw-animate-css` is now a declared dependency.** `dialog`, `sheet` and `tooltip` have used
  `animate-in`, `fade-in-0`, `zoom-in-95` and `slide-in-from-*` since they shipped, but nothing
  in the registry said so and `init` never installed it. Tailwind emits nothing for a class it
  cannot resolve, so a consumer got components with **no animation and no error**. `init` now
  installs the package and adds `@import 'tw-animate-css'` among the leading imports of your
  stylesheet — idempotently, and outside the token block, because an `@import` written into the
  middle of a stylesheet is silently discarded.

### Fixed

- **Tooltip** had no visible arrow. The tip is drawn from the arrow SVG's `background` — a square
  rotated 45° and pulled into the bubble — but only `fill-foreground` was set, so the box was
  transparent and the leftover polygon ended up hidden behind the bubble. Adding `bg-foreground`
  restores it on all four sides.

### Changed — a three-weight line ramp

- `--input` lightens (`oklch(0.885 0.008 254)` → `oklch(0.915 0.007 254)`; dark `17%` → `12%`),
  so a field outline stops competing with page structure.
- New `--border-soft` (`oklch(0.935 0.006 254)`; dark `8%`) for dividers inside an elevated
  surface. `Card`'s slots carry `border-border-soft`, so a `border-b` on `CardHeader` now draws
  the light line automatically. `className="border-b border-border"` restores the old weight.
- `--border` is unchanged: the tabs rail, sidebar, footer and code-block frames look exactly as
  they did.

### Added — Card variants

- **Card** gains `size` (`default | sm`), mirrored to the DOM as `data-size`.
- Card's insets now come from a `--card-spacing` custom property that every slot reads, instead
  of a hard-coded `6`. That is what makes `-mx-(--card-spacing)` edge-to-edge content possible,
  and it stays correct at `size="sm"`. Default rendering is unchanged.
- Four worked examples on the Card page: Size, Login form, Edge-to-edge content, and Image.

### Added — the form cluster

- **Field** — `Field`, `FieldLabel`, `FieldControl`, `FieldDescription`, `FieldError` and
  `FieldGroup`. `Field` generates one id per instance and distributes it, so `htmlFor` ↔ `id`,
  `aria-describedby`, `aria-invalid`, `disabled` and `required` are all wired without the caller
  writing an id or an `aria-*` attribute. `aria-describedby` is built from the parts that
  actually rendered, so it never names a missing element.
- **Label** — a Radix `Label` that dims itself from a disabled `Field`.
- **InputGroup** — puts icons, prefixes and buttons inside the input's border. The nested input
  stays a plain `Input`; the group strips its chrome and owns the focus ring via `focus-within`.
- **ButtonGroup** — joins an input and a button into one control by collapsing the seam between
  their borders.

`input.mdx` is rewritten around these: the sections that told readers to hand-write a `<label>`
or wrap an input in `div.relative` are gone, replaced by twelve worked examples.

### A flatter house style

The three components that carry the most surface area.

### Breaking

- **Badge** drops the `outline`, `ghost` and `link` variants. No variant draws a border any
  more, so a name meaning "border only" had nothing left to describe. `soft` (10% primary tint)
  takes over the low-emphasis coloured role and `muted` the neutral one. A badge that behaves
  like a link should be one — use `asChild`.
- **Tabs** replaces the filled pill group with an underline rail. `TabsTrigger` no longer
  stretches to fill its list; triggers size to their content and align left. Anything relying on
  `flex-1` behaviour needs `className="[&>*]:flex-1"` on the list.

### Added

- `--shadow-card` and `--shadow-card-hover` tokens. The dark value leads with a zero-blur
  `0 0 0 1px` layer, so one utility gives a shadow in light mode and a hairline in dark, where a
  blurred shadow would be invisible.
- **Badge** gains `size` (`sm | default | lg`), which moves padding, text and icon size together,
  and mirrors it to the DOM as `data-size`.

### Changed

- **Card** is separated by elevation instead of a border line.
- **Tabs** handles `orientation="vertical"` layout itself — the extra `flex-row` and `flex-col`
  classes the docs used to ask for are no longer needed.

## 0.1.0

Initial release.

### Components

Nine components, seven documented in full:

- **Button** — six variants, eight sizes, `asChild`.
- **Card** — seven slots with self-adjusting divider spacing.
- **Badge** — six variants matching Button's emphasis levels.
- **Input** — focus and `aria-invalid` states wired to tokens.
- **Dialog** — Radix Dialog with focus trapping and a scroll lock.
- **Tabs** — Radix Tabs, horizontal and vertical.
- **Tooltip** — self-providing, keyboard-accessible.

`Collapsible` and `Sheet` ship as well. They are used by the docs site itself and are
installable, but not yet documented.

### Theming

- Tailwind CSS v4 CSS-first configuration. No `tailwind.config.js`, no `postcss.config.js`.
- Token set defined in `oklch`, derived from the Nongmuek design system: neutrals at hue `254`,
  `--radius` of `0.5rem`, primary stepping from blue-600 to blue-400 in dark mode to hold AA
  contrast.
- Static `brand-50` … `brand-950` ramp for decorative gradients.
- Class-based dark mode with a pre-paint script, so there is no flash of light on load.

### CLI

- `init` — writes `kairo.json`, appends the token block, installs base dependencies.
- `add` — resolves `registryDependencies` transitively and installs npm dependencies in one
  batch.
- `list` — prints the registry.

### Docs

- MDX pages with build-time syntax highlighting via shiki, dual-themed.
- Command palette search on ⌘K.
- Scrollspy table of contents derived from the rendered DOM rather than a source pass.

### Known limitations

- `react-router` carries advisory [GHSA-qwww-vcr4-c8h2](https://github.com/advisories/GHSA-qwww-vcr4-c8h2),
  which affects RSC mode only. This site is a client-rendered SPA and never reaches that code
  path; there is no patched release in the 7.x line yet.
- The `add` command has no `diff` counterpart. Re-adding an updated component overwrites it —
  review the change in git rather than in the CLI.
